# Журнал рішень

Фіксуємо суттєві прийняті рішення з підставою й наслідками. Пропозиції залишаються
у вимогах/дизайні зі своїм статусом. Для складного архітектурного вибору згодом
можна додати окремий ADR, пославшись на нього звідси.

## D-001 — поступове проєктування з документацією

- **Дата:** 2026-10-29.
- **Статус:** прийнято власником у чаті.
- **Контекст:** потрібно виконати перший етап тестового та показати процес роботи з агентом.
- **Рішення:** спочатку вимоги й припущення, потім основні сценарії; рішення обговорювати
  поступово. Зберігати план, вимоги, суттєві рішення, майбутні system design та implementation plan.
- **Наслідки:** документи оновлюються за змістовними етапами. Повний чат не зберігається;
  технічні пропозиції не позначаються як погоджені без відповіді власника.

## D-002 — виконання двох етапів без очікування фідбеку компанії

- **Дата домовленості:** 2026-10-27; зафіксовано в репозиторії 2026-10-29.
- **Статус:** прийнято власником у листуванні з компанією.
- **Контекст:** у первісному ТЗ є обговорення між дизайном та реалізацією;
  пізніше компанія уточнила очікування щодо здачі.
- **Рішення:** проєктування й реалізація виконуються без очікування проміжного погодження компанії.
- **Наслідки:** внутрішнє поступове обговорення з Андрієм зберігається. Невизначеності
  фіксуємо до реалізації; за потреби власник може звернутися до компанії.

Архітектурних рішень поки не прийнято. A-01/A-02 у вимогах — пропозиції агента.
