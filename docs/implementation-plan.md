M2 — перший бізнес-шлях, не готовий реліз із пропущеними гарантіями.
M3–M5 завершують погоджений обсяг. Найраніший технічний доказ M1 —
rollback D1 batch/guard; невдача потребує виправлення підходу до атомарності.

## Перевірки

| Рівень | Інструмент | Приклади |
|---|---|---|
| Чисті правила | Vitest | EPU/minID/fallback, активний Lead, UTC, нормалізація, каталог, типи/ліміти |
| HTTP + D1 у локальному Workers runtime | Vitest | Транзакції/гонки, повтори й дві покупки, auth без мутацій, причинні посилання, lease/ACK, бюджети/cleanup, SC-14 |
| Браузер | Playwright | Квіз, step/reload/Back, A/B після мережевого й локального збою, cookie/Web Lock/sessionStorage, стани звіту |

Браузерна матриця — D-110. Нестабільний обов’язковий тест блокує реліз
до діагностики та повторної перевірки (D-111). Строки/збої моделюємо
керованим часом і фікстурами; не чекаємо реальних 90/180 днів.
Навантажувальні тести й точні p95-вимірювання поза MVP за D-026.

## Демонстрація

1. Синтетичний користувач обирає women + asia; сервер показує 003.
2. CLI з партнерським секретом надсилає Lead для отриманого ClickID.
3. Повторне відкриття у тому самому браузері пропускає квіз і створює
   новий перехід на пріоритетний активний офер.
4. CLI надсилає Purchase; звіт показує правильну атрибуцію.
5. Повтор постбека не змінює чисел; інший PartnerEventID збільшує покупки,
   але не кількість унікальних покупців цього офера.
6. Показати normal/unavailable приймача, попередження та відновлення;
   решту аварійних комбінацій — локальними тестами.

README міститиме точні команди запуску, тестів, CLI, міграції, deploy і
демо. Секрети — через середовище, не Git. Наповнення квізом/CLI;
deploy не очищує базу. SC-14 — тестова фікстура, не підставлені числа UI.

## Умови релізу

- Перед deploy перевірити квоти/тарифи акаунта, Free-доступність binding,
  бюджет Actions і відсутність секретів у bundle/логах. Непідтверджені
  умови зупиняють цей крок, не дозволяють автоматичний платний upgrade.
- Порядок: локальні перевірки → CI/зафіксований локальний доказ → сумісна
  міграція → ручний Worker deploy → smoke. API v1 зберігає незавершені команди.
- Відновлення — після діагностики, без автовідкату даних. Після Time Travel
  чи сумніву в історії бізнес-звіт unavailable до явної перевірки;
  лічильники автоматично не «виправляємо».
- Релізний запис: SHA, команди/результати тестів, браузери, обмеження,
  URL демо; секрети доступу передаються окремо від репозиторію.

Реалізуємо квіз, API, звіт, журнал і фоновий протокол. Імітуємо партнера
та приймач; немає реальних переходів/розсилок. BigQuery, production-масштаб,
Purchase-виключення й автоматичний EPU залишаються в дизайні.
Суттєві приклади AI-роботи записуємо разом із реальними перевірками.
