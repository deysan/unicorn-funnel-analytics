# M2 — внутрішні команди квізу

Історичний запис підкроку. Актуальний підсумок усього M2 на 2026-11-01 —
[фінальний аудит](bmad/reviews/2026-11-01-m2/report.md).

Стан на 2026-10-31: серверний підкрок після
[каталогу](m2-offer-selection.md). Реалізовано читання контексту та
вхід → показ → підтвердження вподобання поверх
[протоколу M1](m1-command-protocol.md). HTTP та UI ще не підключено.

## Контекст і допустимість кроку

`src/server/storage/profile.ts` читає авторизований профіль і компактні
Lead одним SQL-знімком. Перевіряє hash секрету, revoked_at, expired_at
та логічні 180 діб неактивності. UserID не є секретом доступу.
Помилка D1 не маскується під відсутній профіль.

`readQuizContext` повертає допустимі вподобання, email до точної межі
30 діб після підтвердження та `next_action: quiz | select_offer`.
Читання не поновлює активність і нічого не очищає. Наявність самих
відповідей без Lead не пропускає квіз; активний Lead або D-023 має
пріоритет. Стани missing і cookie/bootstrap додасть HTTP-шар.

Q1 доступне без попередніх відповідей, Q2 потребує Q1, email — обох
уподобань. За пріоритету bypass покази й підтвердження недоступні.
`step_not_ready` перевіряється під guard revision навіть для відмови:
після конкурентної зміни сервер перечитує стан, максимум три спроби.
Відмова не займає OperationID і не створює бізнес-записів чи резервів.

## Команди та транзакція

`src/server/quiz/commands.ts` містить внутрішній сервіс
`executeQuizCommand`. Вхід і показ отримують EventID від caller;
EventID підтвердження створює сервер. Підтвердження змінює лише своє
поле; інші допустимі відповіді й email залишаються. Те саме вподобання
з новим OperationID дає новий факт підтвердження без приросту revision.

Показ посилається на вхід; підтвердження — на показ. SQL-guards
перевіряють тип, користувача, преленд, питання та логічні 90 діб перед
commit. Для відповіді перевіряється також вхід її показу. Фізично
наявний, але прострочений запис не придатний для нової команди.

Спільний batch M1 записує подію, pending-доставку, актуальну відповідь,
revision за фактичною зміною, last_active_at, результат і прирости
бюджетів. Повтор повертає попередній результат; новий payload під тим
самим ключем конфліктує. Replay перевіряється до каталогу й доступності
кроку. Один snapshot каталогу зберігається для всіх revision-спроб.
При невідомому результаті запису перевіряємо ключ, не повторюємо batch.

Внутрішні DTO суворі: unknown-поля, null, неправильні enum та ID
відхиляються. UUID тут канонічні lowercase; майбутній HTTP-адаптер
нормалізуватиме uppercase за D-077. Наявність цього сервісу не означає
готовність HTTP-захисту: cookie, Origin, X-Expected-User-ID, ліміт
тіла 8 KiB, rate limit і відображення reason у code/message/retryable
ще підключаються окремо. Email надходитиме лише через команду A.

## Знімок події

JSON із `schema_version: 1` містить event_id/event_type, user_id,
preland_id, серверні occurred_at/received_at; питання додає question_id
та відповідне entry_event_id або view_event_id. Відсутні поля пропускаємо.
Той самий зміст записано в колонках і незмінному експортному JSON до
4 KiB. Значень відповідей, email, секретів і відбитків у подіях немає.
Фонова доставка та очищення ще належать M4.

## Перевірка й межі

Нові D1-тести перевіряють послідовність Q1/Q2/email-view, повтори,
конфлікти, однакові значення, збереження інших відповідей, недоступні
кроки, чужі/відсутні/прострочені посилання й TTL перед commit.
Керовані гонки перевіряють дві вкладки, однаковий ключ, появу Lead,
зміну revision перед відмовою та втрату відповіді після commit.
Переповнення відкочує всі бізнес-ефекти; контекст не змінює активність.

42 нові Worker-випадки пройшли. Фінальний `CI=true npm run check` —
exit 0: **204 Vitest** (81 unit + 123 Worker), типи, збірка та
**21 Playwright**. Браузерні тести поки стосуються каркаса M0,
не нового квізу. Міграції виконувались лише в ізольованих тестових D1.

Незалежне BMAD Build рев’ю не виявило доказових дефектів; рев’юер
читав код і тести, але сам їх не запускав. Технічну межу lowercase
DTO та майбутню HTTP-нормалізацію зафіксовано вище.

Наступний підкрок виконано: [A/B, ClickID і збережений результат](m2-final-commands.md).
Далі — HTTP та клієнтський шлях M2. Коміт після завершення M2.
