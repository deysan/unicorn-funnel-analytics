# Підсумковий аудит M5

Дата: 2026-11-01. База M4: `366ae4fcbde19bbb7cfe045d00579979a2b30983`.
Обсяг — весь M5, включно з успадкованими формулами/HTTP/UI звіту,
SQL підтвердження історії та локальним пакетом демонстрації.
Власник доручив перевірити ТЗ/погоджені рішення з BMAD та зробити один
локальний коміт за успіху. Push, deploy й restore не входять у доручення.

**Висновок: умови локального M5 виконано.** Одне підтверджене зауваження
до передумов повторного демо виправлено; нових бізнес-рішень немає.

## Джерела й метод

[Вимоги](../../../requirements.md) відображають ТЗ, повторно прочитане
2026-11-01 під час аудиту M2. Звірено [рішення](../../../decisions.md),
[SC-14](../../../scenarios.md#sc-14--фільтри-звіту-відвали-та-неадитивність-користувачів)
і [умови M5](../../../implementation-plan.md). Поточний diff охоплює
tracked/untracked зміни, а reviewers читали також незмінений код звіту.

BMAD 6.12.4, bmad-review із resolved
[project override](../../../../_bmad/custom/bmad-review.toml): adversarial,
edge-case-hunter, verification-gap. Три незалежні контексти запущені до
обробки будь-якого результату, без передачі поточних findings між ними.
Квоти проблем немає. Старе design-only формулювання override не скасовує
явного доручення реалізації/аудиту. Редакторські lenses не застосовували:
предмет — поведінка, відповідність вимогам і відтворюваність пакета.

## Findings і виправлення

[Канонічний JSON](findings.json) зберігає висновок adversarial.
Edge-case-hunter та verification-gap повернули порожні переліки.

M5-01: додаткове приватне вікно Chrome не гарантувало нового UserID.
Попередня cookie/Lead могли спричинити bypass і неправильні очікування
приростів. Підтверджено [офіційною довідкою Chrome](https://support.google.com/chrome/answer/95464?hl=en)
2026-11-01. Walkthrough тепер вимагає нової приватної сесії після закриття
всіх попередніх приватних вікон або окремого чистого профілю.
Оригінальний adversarial reviewer повторно прочитав fix і підтвердив
закриття; тести не запускав. Код і тести не змінювалися. Порядок report→baseline→quiz, виправлений
[під час реалізації](../2026-11-01-m5-report/report.md), збережено.

## Фактичні докази та межі

Повний `CI=true npm run check` реалізації M5 завершився **exit 0**:
**534 Vitest (193 unit + 341 Worker), 89 Playwright**
(26+24+6+9+4+2+14+4), типізація/build пройшли.
Лог поза Git: `/tmp/unicorn-m5-check-allowed.log`.

На початку фінального аудиту перевірено: HEAD той самий; source/test diff
побайтово збігається з перевіреним M5. SHA-256 цього diff:
`06230f1b367bdab454791e6e87a820c7bdbf2632cf07e9035be23f12f6e52df5`.
Після нього змінювалася лише документація, тому повний набір без нової
причини не повторювали. Це локальний доказ, не GitHub CI поточного SHA.
Попередній sandbox EPERM був до старту Worker; дозволений запуск пройшов.
Нових невідомих тестових збоїв M5 немає.

Root переглянув desktop/mobile знімки справжнього CLI E2E із test-results:
покупців 1, покупок 2, підписи/точні дроби читаються; мобільна таблиця має
власне прокручування з підказкою. Це знімки тестового runtime, не cloud.
Чотири фактичні секрети середовища перевірено у 238 repo/client/log файлах:
збігів немає, значення не виводилися. Перед комітом перевірено 265 локальних
посилань у 13 змінених Markdown-файлах: цілі існують; JSON валідний,
`git diff --check` пройшов.

Стара dev-історія без доказів не підтверджувалася, persistence не очищувалася.
BigQuery і production-scale залишаються дизайном, партнер/приймач — імітацією.
Restore і хмарні гарантії, p95/навантаження не перевірялися. Одиничний
історичний Q1 503 має лише раніше погоджений [обмежений виняток](../../../m4-q1-incident.md);
не заявляємо його причини/виправлення й не поширюємо виняток на нові збої.
