# План роботи

Оновлено: 2026-10-29. Власник рішень: Андрій. Статус: проєктування.

## Принцип роботи

Розбираємо рішення поступово: вимоги й припущення → основні сценарії → модель
даних → архітектура → гарантії та перевірки → implementation plan.
Суттєві результати зберігаємо в Git, не копіюючи повний чат.
Технічний стек і запропоновані припущення ще не погоджені.

## Етапи

| Етап | Результат | Умова завершення | Стан |
|---|---|---|---|
| 0. Організація | README, AGENTS, журнал AI та рішень, приватний GitHub | Документи перевірені; приватний репозиторій створений і прив'язаний як origin | Готово |
| 1. Вимоги й припущення | `requirements.md` | Ключові невизначеності розібрані; припущення прийняті або мають план уточнення | Початковий перелік підготовлено, обговорення триває |
| 2. Основні сценарії | `scenarios.md` | Для нового й повторного візиту, Lead/Purchase, повторів і відмов визначено очікуваний результат | Заплановано |
| 3. Дані й архітектура | `system-design.md` зі схемами | Зрозумілі відповідальність компонентів, зв'язки, джерела істини, альтернативи й компроміси | Заплановано |
| 4. Надійність, аналітика, безпека | Відповідні розділи system design | Визначені формули, гарантії, SLO, межі накопичення, витрати та перевірки | Заплановано |
| 5. План MVP | `implementation-plan.md` | Кроки мають залежності, критерії завершення й перевірки; визначений мінімальний наскрізний зріз | Заплановано |
| 6. Реалізація та демонстрація | Код, тести, CI, демо, README | Відтворюється погоджений сценарій, показано обмеження й результати перевірок | Пізніше, за межами поточного обговорення |

## Запропонований мінімальний наскрізний зріз

Квіз → збережені відповіді й події → серверний вибір офера → зафіксований перехід
→ тестовий Lead → повторний візит без квізу → Purchase → зміна звіту.
Перевірки включають повтор того самого постбека та другу окрему покупку.

Це початкова пропозиція агента за сценарієм ТЗ, не остаточна декомпозиція робіт.

## Пріоритет найближчого обговорення

1. Межі ідентифікації користувача та доменів прелендів (Q-01).
2. Візит, повторне проходження, достатність відповідей (Q-02, Q-03).
3. Послідовно пройти сценарії та визначити граничні випадки.
