## Поведінка

Корінь `/` показує український квіз Q1 → Q2 → email → назва офера,
URL і ClickID. women + asia дає 003. URL показується текстом, без
переходу на партнера; листи не надсилаються. Діагностика з’єднання
збережена на `/diagnostics`. Радіокнопки й email мають labels,
клавіатурне керування, стан pending/error та фокус заголовка кроку.

`step` обмежується прийнятими сервером відповідями; без параметра — Q1.
Новий документ створює новий entry; Back/Forward усередині документа —
новий view. Controller живе поза React render, view надсилається тільки
після відображення питання; до ACK підтвердження вимкнено. React
StrictMode не повторює факти. Повтори зберігають ключ і payload дії.

Власний фінальний draft із версією, користувачем, посиланнями й строком
зберігається одним JSON у sessionStorage до A. A видаляє email із draft;
помилка цього запису зупиняє B і залишає ключі в пам’яті для ручного
відновлення. Відновлення читає B, потім A, й надсилає тільки відсутнє.
Свіжий server_time визначає 24-годинну межу; після неї залишаються лише
ідентифікатори для GET. Невідома версія, хибні фази/посилання або payload
не надсилаються. Результат доступний за `?result=<operation_id>` лише
через власний draft: reload відновлює B, новий `/` починає новий вхід.
No_offer зберігається; лише явна кнопка створює нову B.

Bootstrap перечитує контекст під exclusive Web Lock, створює профіль
і перевіряє повернення cookie. Підтверджений профіль працює без Web Locks;
створення нового — ні. Позначка незавершеного bootstrap переживає reload,
тому заблокована cookie не породжує автоматичний цикл профілів.
Втрата доступу приховує дані, зупиняє команди та вимагає явного відновлення.
429/503 limiter мають паузу за валідним Retry-After плюс 0–10% jitter;
60/30 секунд застосовуються лише як fallback. Максимум три автоматичні
повтори. Мережа/10s timeout
потребують ручного повтору. Пауза не утримує Web Lock.

## HTTP і збереження

Hono routes `/api/v1/quiz` використовують наявний executor, перевірку
посилань і бюджети. POST вимагає точного Origin із конфігу, JSON UTF-8,
без compression; body reader рахує фактичні байти до 8192. UUID v4
нормалізуються лише в ID-полях, зайві поля й клієнтський `type` відхиляються.
Клієнт перевіряє DTO відповідей перед використанням.

Cookie `__Host-unicorn` містить 32 випадкові байти base64url; D1 зберігає
SHA-256 вихідних байтів. Атрибути HttpOnly/Secure/SameSite=Lax/Path=/,
без Domain; строк 180 діб перевіряється сервером. Cookie авторизує,
X-Expected-User-ID лише звіряє контекст. Чужий ID не стирає cookie.
GET і replay не продовжують строк. Власний успішний commit повідомляє
адаптер через внутрішній callback; час активності береться з UPDATE
RETURNING того самого batch. Невідомий commit не видається за новий.
Профіль і резерв profiles створюються атомарно.

IP 300/60s, UserID 120/60s, bootstrap 10/60s — реальні локальні Workers
bindings. Сумарний час очікування викликів limiter ≤1s; пізній успіх
не запускає бізнес-команду. IP HMAC має окремий секрет. Локальна
синтетична адреса допустима тільки для loopback URL; forwarded headers
ігноруються. Цей build свідомо fail-closed поза loopback, а не готовий
cloud adapter. Перед deploy потрібні справжній довірений Cloudflare IP,
актуальні Free-передумови, дозволені origins і хмарні secrets/bindings.

## Запуск і ізоляція

`npm run dev` спочатку створює лише відсутні `.dev.vars` секрети й
додавально застосовує міграції 0001–0004 до `.wrangler/state`, яку читає
Vite. Dev-дані не очищуються. Окремий `npm run setup:local` повторює цю
підготовку. `.dev.vars.example` містить тільки placeholders.

`npm run check` готує відсутні локальні секрети й self-signed TLS-сертифікат
у `.wrangler/tls`, перевіряє типи, Vitest, збірку й Playwright. Потрібен
OpenSSL. Браузери працюють проти `https://localhost:4173`.
WebKit не прийняв Secure cookie через HTTP localhost, тому локальний
runtime переведено на HTTPS. Playwright ігнорує лише помилку довіри до
локального сертифіката; cookie-захист залишається повним.
E2E видаляє тільки `.wrangler/e2e-state`, застосовує міграції й серверно
створює синтетичні профілі для тестів. Їхні cookies не потрапляють у Git;
публічного test/admin API немає. Ліміти й budgets для тестів незмінні.
Повний smoke запускається двома окремими групами: Chromium і решта
браузерної матриці, кожна зі своїм стартом isolated runtime. Так тести
не витрачають понад реальний IP300/min одного локального клієнта.
Групи мають різні outputDir; скриншоти не стираються наступною групою.
Перевірки станів можуть дочекатися погодженої 30s limiter-паузи: один
діагностований запуск Miniflare повернув SQLITE_BUSY зі свого rate binding,
а API коректно відповів fail-closed 503. Автоповторів самих тестів немає.

Окремо перевірено тимчасову копію без `.dev.vars`, `.wrangler/tls` і
згенерованих Worker-типів: typecheck/build проходять, prebuild створює
відсутні локальні файли, повторний setup зберігає секрети. Встановлені
залежності використані з наявного node_modules; це не новий запуск npm ci.
Основна dev-база й наявні секрети цією перевіркою не змінювалися.

## Перевірені гілки

Фінальний `CI=true npm run check` — exit 0: **295 Vitest**
(119 unit + 176 Worker), типи/build та **48 Playwright**
(24 Chromium + 24 у решті матриці). `git diff --check` і перевірка
локальних посилань пройшли. Переглянуті desktop/mobile скриншоти email
і результату; URL/ClickID не створюють горизонтального переповнення.
Перевірка client bundle не знайшла значень двох локальних секретів.
Незалежне BMAD Build review завершено трьома шарами: blind, edge case,
verification gap. Виправлено прийняття іншого UserID після browser Back
або answer, додано негативні HTTP-тести UserID/bootstrap limiter.
Окремо виправлено повідомлення timeout/abort очікування Web Lock.
Після поправок основний агент виконав наведений повний check, exit 0.
Усі зауваження цього рев’ю закриті; [triage](bmad/implementation-artifacts/spec-m2-http-ui.md).

- Worker/D1: bootstrap/profile budget, cookie/replay/result ownership,
  Origin/JSON/UUID/extra fields, TTL/revocation, capacity і limiter failure,
  сукупна межа очікування, повний HTTP A/B → 003 і 410 результату.
- Unit: strict versioned draft, фази/посилання/email, точна межа TTL,
  видалення payload зі збереженням ключів і DTO відповідей.
- У всій браузерній матриці: робочий квіз, result reload з тим самим
  ClickID, свіжий `/`, справжня Secure cookie та bootstrap двох вкладок.
- Chromium: lost A/B, question reload/Back, no_offer з незмінним ключем
  нової B при retry, storage failure до/після A, блокування й втрата cookie,
  TTL на reload та в активній вкладці, Retry-After і максимум три цикли,
  Web Locks, Lead bypass без штучного email. Частина аварійних відповідей
  моделюється Playwright routes; основний шлях і lost-response commit
  використовують реальні HTTP/D1.
- Регресії рев’ю: зміна cookie перед browser Back із результату або
  між answer і context зупиняє старий квіз без POST нового власника;
  timeout/abort Web Lock показує причину й дозволяє ручний retry.

## Межі

## Уточнення фінального аудиту M2, 2026-11-01

Pending marker початкової видачі тепер перевіряється і при автоматичному
повторі restart. Очищує його лише явна дія відновлення; готовий контекст
повторно використовує чинний профіль. Це закриває зайві POST після
успішного restart із втраченою cookie та 429 на контрольному читанні.
Browser-регресія перевіряє відсутність третьої видачі після паузи.

Спільний HTTP-адаптер результату B зберігає demo JSON та cookie-заголовки.
Окреме redirect-представлення (303/Location) перевірено in-process на
реальному збереженому результаті, без відкриття партнера. Наявний
публічний API не перемикається на зовнішній redirect. Додано також
точну browser-перевірку залежного заголовка Q2 після women → Back → men.
