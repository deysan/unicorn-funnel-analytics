## Звірка обсягу

Основні формули й UI звіту реалізовано у M2; M4 додав технічний стан
Cron/доставки й очищення. M5 доповнює операційну перевірку повноти
історії та відтворюваний пакет для перевіряючого.

| D-014, групи входу й пізні результати | Період визначає групу; результат прив’язаний до конкретного ClickID | Той самий набір: cross-day, early/late Purchase, bypass, повторні покази |

## Межі операційного підтвердження

Позитивні прапорці у відновленій D1, однакові лічильники та успішний Cron
не доводять повноти історії. Потрібен зовнішній доказ і явне рішення
оператора за D-098/D-116. SQL лише перевіряє технічні передумови запису
метаданих. Немає нового admin UI чи дозволу виконати restore.

## Реалізований пакет і перевірки

Додано [операційну процедуру](report-operations.md),
[демонстрацію](demo-walkthrough.md), guarded SQL helpers і 17 нових
D1-перевірок. Бізнес-формули та API не змінювалися.

Повний локальний check: **534 Vitest, 89 Playwright**, типізація/build,
exit 0. Три BMAD reviewers знайшли одну помилку порядку кроків демо;
виправлено й підтверджено повторним читанням. [Докази та межі](bmad/reviews/2026-11-01-m5-report/report.md).

M5 завершено після [підсумкової звірки](bmad/reviews/2026-11-01-m5/report.md).
Уточнено чисту приватну сесію для повторного демо; код/тести незмінні
від успішного check. Власник дозволив один локальний коміт. Хмарні передумови,
реальний deploy і smoke належать M6; SQL проти dev та restore не виконувалися.
